# Cupbox · Android QQ 机器人 1.0.0

原生 Android QQ 机器人，保留 Cupbox Logo 与柔和配色，**全程强制竖屏**。重做首页、登录与设置流程，加入原 Logo 启动动画、真实下载进度、安装阶段提示和离线冷知识；内置 Ubuntu 基础环境与蓝色大肥鱼人设。1.0.0 新增关于页面、应用属性、联系方式与 GitHub 更新检查。

## 安装

最新签名包：[1.0.1 Release](https://github.com/beizilaoshi/Cupbox-Android-Qbot/releases/tag/v1.0.1)，文件名 `Cupbox-Android-Qbot-1.0.1-release.apk`，129.5 MiB（内置两种架构的 Ubuntu 基础环境）。支持 Android 8.0 及以上的 **64 位 ARM / x86** 设备。

将 APK 复制到手机，允许文件管理器安装应用后打开安装。不要将调试版与发布版混装。

**签名变更（1.0.1 起）**：1.0.0 的发布密钥已不可用，1.0.1 使用新的发布密钥（证书 SHA-256 `C0:3E:71:F8:9F:47:97:64:D6:16:F1:46:60:B7:01:47:9B:93:B5:31:42:54:A3:FC:9C:D8:4A:B2:2F:8A:60:53`）。Android 不允许签名不同的包互相覆盖，因此 **1.0.0 用户需要先卸载再安装**，卸载会删除应用内的配置、会话记忆与 QQ 登录资料。从 1.0.1 起请保管好 `.keys/cupbox-release.jks` 与 `signing.properties`，后续版本可正常覆盖升级。每个安装包的 SHA-256 与 APK 一起发布。

## 1.0.1 修复与优化

1.0.1 是 1.0.0 之后的维护版本，只改行为与稳定性，不改变安装方式和登录路线。

- 修复：推理模型输出**未闭合**的 `<think>` 段时，思考内容会被当成正文发到 QQ。
- 修复：暂停或忙碌期间被丢弃的消息也被计入「已触发」，导致首页统计偏高。
- 修复：回复成功后在主线程写会话记忆，长时间使用可能出现卡顿。
- 修复：切换人格、登录方式时在控件自己的回调里重建界面，存在控件被销毁的闪退风险。
- 修复：重试本机环境时继续显示上一次的失败原因；二维码等待阶段继续显示安装阶段的百分比。
- 优化：群号与关键词支持「、」「；」和空格分隔，并对群号、关键词增加长度上限提示。
- 优化：记忆数据库开启 WAL，主线程读与工作线程写不再互相阻塞。
- 优化：运行记录支持一键复制，便于反馈问题。
- 构建：CI 显式安装 `build-tools;35.0.0`（AGP 8.7.3 默认要求），并增加并发取消、超时和产物缺失即失败。

`versionCode` 从 4 升到 5。**注意：本版本换了新的发布签名，1.0.0 需要先卸载再安装**，详见下方「安装」一节。

## 手机本机登录（默认）

1. 首页按「登录 QQ → 对话模型 → 回复范围」逐步设置；主按钮会提示下一项未完成的操作。「人格」和「设置」独立放在底部。
2. 点击「第一步 · 登录 QQ → 进入本机登录 → 准备并启动本机 QQ」。Ubuntu 基础环境随 APK 内置并校验，PRoot、BusyBox、运行脚本、端口及协议设置已内置或自动完成。无需 root、电脑常驻或额外安装 Termux。
3. **至少预留 3 GB 空间**。QQ、NapCat 和系统依赖仍需要联网下载；首次可能需要数分钟。复制、下载显示当前文件的真实字节数与百分比，安装和启动显示阶段与不定进度，不把阶段数伪装成总耗时百分比。
4. 等待时每 9 秒轮播一条离线通用冷知识，不联网也不调用模型。可以停止准备、失败重试，已校验的文件和已完成环境会复用。
5. 出现二维码后，用 QQ 扫码并在手机确认。切到 QQ 时服务继续运行；应用不绕过设备验证。
6. 返回首页设置模型 API 地址、Key 和模型 ID，先测试连接，再保存。模型测试有等待进度、冷知识和取消操作；地址填写到 `/v1`。
7. 设置允许回复的群号、私聊开关与触发方式；在「人格」选择内置大肥鱼或其他人设。修改后底部出现固定保存栏，跨页面保留草稿。
8. 首页连接机器人，再手动开启自动回复。首次开启前核对实际发送范围。启动动画使用原 Logo 的轻量缩放、淡入和回弹；系统关闭动画时跳过。

本机登录采用 **PRoot → Ubuntu → Linux QQ + NapCat → 本机 OneBot** 的路线。NapCat 管理和 OneBot 接口只绑定回环地址，使用独立随机端口与随机 Token；二维码在本机生成。

停止机器人回复与停止 QQ 登录环境是两个操作：首页的「断开机器人」只停止对话机器人；登录页或通知栏的「停止本机 QQ」会停止本机 QQ 及其机器人连接。程序按独立进程组清理 Linux 子进程，保留登录资料供下次恢复。

本机模式使用更多内存、电量和存储，并在前台服务期间持有有超时保护的部分唤醒锁。系统强制停止、手机重启后需手动启动，不自动恢复群发言。不同厂商的后台限制仍需真机核对。

## 远程 OneBot（可选）

如果已有 QQ 协议端，可关闭「使用本机 QQ」，填写正向 WebSocket 地址与 Access Token。协议端消息格式须为 `array`，建议启用心跳。局域网示例 `ws://192.168.1.10:3001`；`127.0.0.1` 指手机本身。公网请使用 `wss://`。

旧版已保存非空 OneBot 地址的配置，会默认保留远程模式，避免升级时意外切换。

## 蓝色大肥鱼

「人格」选择 **蓝色大肥鱼**，使用桌面版引入的 MIT 授权鲸鱼娘原版人设：嘴贫、有主见、平级群友，短句接梗、喜欢白米饭、被叫大肥鱼会炸毛。人设来源、原文、规则与许可证在 `app/src/main/assets/whale/`。

默认使用原版人设，不混入自定义设定。开启「自由演绎」后才结合附加设定；可直接查看原文。模型的实际表达取决于所选模型，不保证每次完全符合角色。

Android 版补充了真实身份与能力边界：被问及真实身份时如实说明是 AI 角色；当前只支持文本，不冒充已经识图、发图或执行工具。未接入的 `[表情:情绪]` 标记会清理，不作为文字发到 QQ。

当前未移植桌面端的表情图库、识图、插件、搜索和本地文件工具，也不包含 AstrBot 框架与插件生态。

## 机器人规则与数据

- 默认群白名单为空、私聊关闭、自动回复关闭。真实 @ 与关键词为「或」关系；空白名单不回复群聊。
- 群白名单 / 黑名单 / 所有群、私聊开关、回复 @、同会话冷却、每分钟上限、去重和单请求处理继续有效。
- 只有收到 QQ 成功投递回执才写入会话记忆，结果未知时不自动重发。暂停会取消未完成请求，无法撤回已经发出的消息。
- 最多 32 个记忆会话、每会话 20 条、80 条日志；只记已触发并成功投递的对话，不收集旁听。
- 模型密钥与配置使用 Android Keystore AES-GCM 加密；会话历史是应用私有数据库中的本机明文。开启记忆后，相应历史会提交给模型服务。
- QQ 登录资料保存在应用私有运行目录。清空对话记忆不会删除 QQ 登录；清除应用数据或卸载会删除运行环境、配置与登录资料。

## 构建与签名

运行 `python scripts/prepare-bundles.py` 可校验或重新准备内置基础镜像；`scripts/build.ps1` 与 GitHub Actions 会自动执行。大型基础镜像作为构建输入按固定 SHA-256 获取，不写入 Git 历史；构建的 APK 仍然内置镜像。直接运行 Gradle 构建 APK 前也请执行该准备脚本。

需要 JDK 17–21、Android SDK 35、Build Tools 34、Google Maven / Maven Central 网络。已提交的原生组件支持 `arm64-v8a` 与 `x86_64`，不需要本机 NDK 编译。

```powershell
./scripts/build.ps1
./scripts/build.ps1 -DebugBuild
./gradlew.bat testDebugUnitTest lintDebug
# 以下仅在专用测试设备运行，会清除测试应用的对话配置与记忆
./gradlew.bat connectedDebugAndroidTest
```

大型本机登录验收为显式启用的 `LocalLoginDeviceTest`，需加 `fullRuntime=true` 参数；常规测试不自动下载系统环境。原生二进制与包哈希见 [docs/native-manifest.json](docs/native-manifest.json)，提取脚本为 `scripts/prepare-native.py`。

备份 `.keys/cupbox-release.jks` 和 `signing.properties`，后续升级必须使用同一签名；两者均被 Git 忽略，不要分发。源码、说明与截图在本地项目中，APK 位于 `release/`。
